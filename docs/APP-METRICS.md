# App and subsystem measurements

Process grouping assigns processes by active AI agent session, container cgroup, systemd service or scope, then **Other / not attributed**. A process belongs to one group. The collector reads `/proc/<pid>/stat`, `io`, and `cgroup`; it never reads command lines or environment variables. When a group's cgroup v2 paths are exclusive, it uses `cpu.stat`, `memory.current`, `memory.stat`, and `io.stat`. Otherwise it sums readable process counters. The first sample establishes a counter baseline, so rates become available after a second sample.

CPU is shown as a percentage of one core and can exceed 100%. Memory is cgroup current usage where available, otherwise summed resident memory. File cache is shown from cgroup `memory.stat`. Disk rates use read and write counter deltas; app and drive bytes today are accumulated in the server by UTC day and survive agent restarts. Container network uses the container network namespace's interface counters when readable. Network use for other groups is not measured. Estimated energy allocates measured CPU package watts by app CPU time share; it is not wall power or a direct app measurement.

The API reconciles the current CPU, memory, drive I/O and network shares to their corresponding host totals. **Other / not attributed** receives the remainder. If process accounting exceeds a host total (for example because resident pages are shared), the displayed shares are scaled to that total. Interfaces and drives whose counters cannot be read are excluded from reconciliation. The source counters and coverage remain visible in the Machine view.

The GPU tab appears only when `/sys/class/drm` exposes a card. The current driver probe reads `gpu_busy_percent` where available; per-app GPU use is shown as not measured.

`GET /api/v1/hosts/{id}/apps?range=1h|12h|24h|7d|30d` returns current app groups, minute history for the first three ranges, hourly history for the last two, and hourly leaders for the past 48 hours. Browser history is sampled to at most about 120 points per app. Minute app history is retained for 24 hours; hourly aggregates are retained for 30 days. `GET /api/v1/hosts/{id}/traffic` returns observed interface traffic for today, seven days and thirty days. These endpoints use the existing read API access control. No new helper endpoint or privilege is needed.

Internal TCP and HTTP checks run independently of managed file checks. Each executed failure is sent to the overview and probe history; the first failed check is a warning in the overview and remains unconfirmed in availability history. The second consecutive failed check is Down in both. A successful check clears the failure count. Stale means the check stopped reporting. The same confirmation applies to failed configured status and backup checks.
